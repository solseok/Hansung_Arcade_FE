## 빌드 · 실행

### JDK 21 설치
JDK 미설치 시 먼저 설치합니다. 설치되어 있다면, 건너뛰셔도 됩니다.
```bash
# macOS (Homebrew)
brew install --cask temurin@21
```

Windows의 경우
```bat
winget install EclipseAdoptium.Temurin.21.JDK
```

설치 후 `java -version`으로 확인하세요. Windows는 cmd 창을 새로 열어야 `java`를 인식합니다.

### 빌드, 실행, 테스트

```bash
# Linux, macOS, Git bash
./gradlew build                      # 컴파일 + 테스트
./gradlew run                        # 실행
./gradlew clean test                 # 캐시 없이 테스트 실행
```

`permission denied`가 나오면 `chmod +x gradlew`를 한 번 실행한 뒤 다시 시도하세요.

Windows의 경우
```bat
gradlew build
gradlew run
gradlew clean test
```

PowerShell에서는 앞에 `.\`를 붙입니다. 예: `.\gradlew build`

### 테스트 결과

`build/reports/tests/test/index.html`을 브라우저로 열면 테스트 결과를 볼 수 있습니다.

## 아웃게임 목업 실행

기본 실행은 로그인입니다. 배경은 800x600 그림(`resources/etc/hsu_arcade.png`)을 창 전체에 깔고, 아래 가운데 입력 영역 양옆의
1P·2P를 고르고 1P면 닉네임 1개·2P면 2개를 입력합니다(2P면 입력 영역이 넓어집니다). [시작하기]·[종   료]는 입력 영역 바로 아래에 있습니다.
닉네임은 2~8자이고 ㅁㄴㅇㄹ처럼 완성되지 않은 한글이나 숫자로만 된 닉네임은 받지 않습니다(규칙 안내 문구는 두지 않고 어긋날 때만 이유를 보여 줍니다). 닉네임 칸은 가장 넓은 8자가 꽉 차는 폭입니다. 서버 주소·포트는 입력하지 않고
`application.properties`의 `network.host=${SERVER_HOST}`·`network.port=${SERVER_PORT}` 자리표시자를 `.env`로 채웁니다(아래 서버 접속).
`--app.start-screen=lobby`로 로비에 바로 들어갈 수 있습니다.

### 서버 접속 (온라인 로그인)

`.env.example`을 프로젝트 폴더에 `.env`로 복사해 `SERVER_HOST`·`SERVER_PORT`를 채운 뒤 온라인 모드로 실행합니다.
`.env`는 커밋하지 않습니다. 같은 이름의 환경 변수가 있으면 그 값이, 실행 인자 `--network.host=...`가 있으면 그 값이 앞섭니다.

```bash
./gradlew run --args="--network.mode=online"
```

[시작하기]를 누르면 그때 서버에 접속해(TCP, 한 줄 JSON) HELLO를 확인하고 LOGIN을 보냅니다. 기다리는 동안 입력이 막히고,
서버가 거절하면(닉네임 중복 등) 서버 문구를 오류 줄에 보여 줍니다. 로그인한 뒤에는 5초마다 PING을 보내고, 게임을 끝내면 BYE를 보냅니다.
연결이 끊기면 로그인 화면으로 돌아가 이유를 보여 줍니다.
기본값 `network.mode=offline`은 `.env` 없이 지금처럼 서버 없이 실행합니다.

온라인이면 로비·대기실·경기 모두 서버를 따릅니다(`ServerLobbyService`, `ServerMatchLink`). 서버는 Hansung_Arcade_BE `develop`
(방 API #8, 인게임 경기 #4, 아이템 획득·흩뿌리기 #10이 합쳐진 버전)이어야 합니다.

- 로비: 들어올 때 ROOM_LIST로 목록을 받고, 다른 사람이 방을 만들거나 들어가고 나가면 서버가 보내는 LOBBY_ROOMS로 바로 다시 그립니다.
  방 만들기·입장·바로시작이 거절되면(자리 없음, 게임 중 등) 서버 문구를 안내 줄에 보여 줍니다.
- 대기실: 자리·캐릭터·팀 색·방장·준비는 서버의 ROOM_STATE를 그대로 그립니다(목업 참가자 없음). 캐릭터·팀·준비·맵(방장)·채팅은
  서버로 보내고, 채팅과 입장·퇴장·방장 안내는 서버가 돌려준 CHAT_MESSAGE로 뜹니다. 서버가 거절하면 채팅 창에 이유가 뜹니다.
- 방장이 게임을 시작하면 GAME_STARTED를 받은 모두가 시작 페이드 뒤 서버가 정한 맵·캐릭터(랜덤은 서버가 정함)·스폰 자리에
  경기 인원 모두를 세운 게임 화면에 들어가고 LOADED를 보냅니다. 모두 LOADED를 보내 ROUND_BEGIN이 올 때까지는 검은 화면에서 기다리고,
  카운트다운(3초)이 끝나는 순간에 맞춰 "Ready... Start!" 연출이 끝나며 그때부터 움직이고 경기 시계가 흐릅니다.
  페이드 동안 온 경기 푸시(상대가 이미 나가 끝난 경기 등)는 모아 두었다가 게임 화면을 띄울 때 넣습니다.
- 경기 판정은 서버가 합니다(`ServerRules`). 내 캐릭터는 키로 움직여 자리를 MOVE로 보내고(초당 20번, 바뀌었을 때만),
  다른 사람은 PLAYER_MOVED로 받은 자리로 따라갑니다. 물풍선 키는 BALLOON_PLACE만 보내고 BALLOON_PLACED가 오면 놓으며,
  터지는 때·물줄기 길이·부서진 블럭·나온 아이템은 BALLOON_EXPLODED를 따릅니다. 아이템 칸에 들어서면 ITEM_PICKUP을 보내고
  먹은 것과 능력치는 ITEM_TAKEN을 따릅니다. 갇힘·구출·탈락·흩뿌리기·나감은 PLAYER_TRAPPED, PLAYER_RESCUED, PLAYER_POPPED,
  ITEM_SCATTERED, PLAYER_LEFT를, 승패는 GAME_OVER를 따릅니다. 경기 중 채팅도 서버로 보내고 돌려받은 글만 맵 위에 올립니다.
- 비행기는 AIRPLANE_APPEARED가 오면 띄우고(스스로 출현 시각을 세지 않음), ITEM_DROPPED로 받은 아이템만 떨어뜨려 닿으면 놓습니다.
  떨어지는 사이 물줄기에 사라지거나 누가 먹으면 놓지 않고, 내 발밑에 닿으면 ITEM_PICKUP을 보냅니다.
- 아이템 키는 손에 든 쓰는 아이템을 ITEM_USE로 보내기만 하고, 바늘(빠져나오기)·보호막·스프링 신발(서버가 정한 칸으로 점프)의 효과와
  남은 개수는 ITEM_USED를 따릅니다. 손에 든 아이템은 ITEM_TAKEN의 heldItem·heldCount를 따릅니다.
- 서버가 아직 다루지 않는 것(물풍선 밀기·던지기, 밀리는 상자)은 온라인 경기에서 하지 않습니다.
  흩뿌려진 아이템은 날아가는 연출 없이 서버가 정한 칸에 바로 놓입니다.
- 서버가 GAME_OVER를 보내면 결과 모달을 띄운 뒤 대기실로 돌아옵니다. 온라인에는 목업 경기 끝내기 버튼이 없고, 인게임 나가기는
  GAME_EXIT를 보내고 로비로 갑니다. 로딩 시간 초과로 서버가 경기에서 빼면 GAME_EXIT 없이 로비로 갑니다.
  서버 경기가 끝나기 전까지 대기실의 고르기·준비·맵은 잠깁니다.
- 1P·2P 캐릭터·팀은 따로 고를 수 있지만, 지금 서버(`ref/outgame-room`)는 고르기를 연결 단위로 받아 1P·2P에 같은 값을 돌려줍니다.
  클라이언트는 고른 사람의 번호(`playerId`)를 함께 보내므로 서버가 플레이어별로 받게 되면 그대로 따로 적용됩니다.
- 나가기가 서버와 어긋나도(응답이 늦음 등) 로비로 가고, 로비에서 목록을 받을 때 서버가 아직 방에 두고 있으면 빼낸 뒤 다시 받습니다.

로비는 탭 없이 한 목록에 바로 들어갈 수 있는 대기 방 → 가득 찬 대기 방 → 게임 중인 방 순으로 8개씩 보여 주고,
목록 아래로 튀어나온 자리의 ◁ ▷ 버튼으로 쪽을 넘깁니다. 방 칸을 누르면 "입장하시겠습니까?"를 묻고,
게임 중이거나 가득 찬 방은 안내만 합니다. 방 만들기 정원은 2~8명입니다.
대기실은 왼쪽에 방 제목줄·8자리(방   장·준   비 불 켜짐/꺼짐)·채팅, 오른쪽에 캐릭터(? = 랜덤)·팀 8색·맵(방장만 선택, 랜덤 포함)·
준비/게임 시작이 있습니다. 캐릭터는 팀 색으로 옷·모자 같은 고정색을 다시 칠해 보여 줍니다(CharacterRecolor).
맵 최대 인원은 캠프·패트릿 8명, 빌리지 6명이고, 맵을 바꾸면 방 정원이 그에 맞게 바뀝니다.

로비·대기실의 배치와 색은 `outgame/ui`의 `WaitingRoomLayout`·`LobbyLayout`·`OutgamePalette`에, 로그인 입력 영역 배치는 `LoginPanel`, 결과 모달 색은 `ResultOverlay`에 있습니다. 도형과 글자는 안티앨리어싱으로 그립니다.
글꼴은 두 가지입니다. 방 제목·닉네임·채팅처럼 사용자가 바꿀 수 있는 문구는 굴림체(윈도우 설치본, 맥은 MS 오피스의 gulim.ttc,
둘 다 없으면 기본 고정폭), 버튼·상태처럼 바뀌지 않는 문구는 굵은 산세리프에 테두리·그러데이션을 입혀 씁니다.
사용자가 알려 준 색과 참고 화면 PNG는 맥 스크린샷(Display P3) 값이라 `OutgamePalette.p3`로 sRGB로 바꿔 넣습니다.

오프라인(`network.mode=offline`)에서는 다른 참가자가 준비된 목업입니다. 참가자의 준비는 로컬 상태만 바꾸며 서버로 전달하지 않습니다.
게임 시작은 선택한 맵·캐릭터로 이 컴퓨터의 플레이어만 넣은 인게임을 실행합니다.
오프라인 인게임 아래의 ‘목업 경기 끝내기’는 마지막 플레이어가 죽은 상황을 흉내 냅니다. 1.5초 뒤 맵 프레임 아래에서
`| NAME | KILL | SAVE |` 결과 모달(8명이 들어가는 고정 크기, 이 컴퓨터의 플레이어 줄은 노란 글자)이 올라오고,
8.5초에 화면이 검게 어두워진 뒤 원래 대기방으로 돌아갑니다.
돌아올 때 방 인원을 유지하고, ‘로비로 나가기’에서만 퇴장합니다. 인게임 오른쪽 아래 ‘나가기’를 누르면 경기를 그만두고 대기방으로 돌아갑니다
(인게임 직접 실행에서는 창을 닫습니다).

2P(한 컴퓨터 2인)로 들어오면 대기실의 캐릭터 칸·팀 색 칸을 **왼쪽 클릭하면 1P, 오른쪽 클릭하면 2P**의 것을 고릅니다(맥은 Ctrl+클릭도 오른쪽 클릭으로 칩니다).
칸에는 고른 사람의 `1P`(빨강)·`2P`(파랑) 딱지가 붙고, 2P는 처음에 한성냥이·파랑으로 시작합니다.

방장이 ‘게임 시작’을 누르면 대기실이 0.3초 동안 검게 어두워진 뒤 게임으로 넘어갑니다. 어두워지는 동안에는 마우스·키 입력을 받지 않습니다.
게임은 크레이지아케이드 플레이 영상의 흐름을 따른 “Ready... Start!” 연출로 시작합니다. 0.5초 동안 화면이 완전히 검고
Ready 소리가 나며, 이어서 START!! 글자가 뜬 채로 0.5초 동안 맵과 함께 밝아집니다(Start 소리). START!!는 0.75초 뒤부터
0.75초 동안 왼쪽 글자부터 한 자씩 위로 튀어 올라 사라지고(느낌표 둘은 함께), 다 사라진 순간부터 조작할 수 있습니다.
경기 시계는 START!! 글자가 뜰 때부터 흘러, 조작할 수 있게 될 때 타이머는 02:59입니다.
START!! 글자가 뜬 뒤부터 사라지고 0.8초 뒤까지 내 캐릭터 머리 바로 위에 팀 색 화살표가 뜨고(맨 윗줄이면 발 아래에서 위로),
2인 모드면 화살표에 `1P`·`2P`를 적습니다. START!! 글자(`resources/intro/game_start.bmp`의 아랫줄)와 화살표(`player_pos.bmp`)는
사용자가 제공한 GAME-CrazyAcade 프로젝트 그림을 쓰고, 그림에서 위아래가 뒤집혀 있던 느낌표는 바로 세우며,
화살표는 팀 색으로 다시 칠합니다(`IntroSprites`).
경기 중에는 모든 캐릭터 머리 위에 닉네임이 뜹니다(맨 윗줄이면 발 아래).
블럭이 부서지면 33% 확률로 아이템 그림이 있는 11종이 모두 나옵니다(비율은 `ItemDrops.WEIGHTS`, 물풍선·물줄기·롤러 신발이 합쳐 60%).

물줄기 판정은 크아 개발자 설명(넥슨 ‘넥아알려줄게’ 걸치기 편)을 따릅니다. 캐릭터 충돌 박스가 물줄기와 66% 이상 겹칠 때만 갇히고, 겹침은 박스가 걸친 가로 줄·세로 열마다 따로 잽니다. 그래서 네 칸이 만나는 곳에 걸쳐 서면 바로 옆에서 터진 십자 물줄기에도 갇히지 않습니다(걸치기). 바닥 가시(`!`) 칸에 놓거나 미끄러져 들어오거나 내려앉은 물풍선은 물줄기가 남은 칸처럼 바로 터집니다.

메뉴에서 음소거할 수 있습니다. BGM은 화면마다 전용 곡을 씁니다(`Sound.bgmFor`): 로그인 `01. login`, 로비 `02. lobby`,
대기실 `03. room`이고, 게임은 맵마다 `Camp`·`Patrit`·`Village`를 씁니다(`Sound.bgmForMap`).
게임 시작 연출에 Ntc_GameReady → Ntc_GameStart, 경기가 끝날 때 Ntc_GameEnd를 재생합니다.
인게임 효과음(물풍선 놓기·터짐·연쇄, 차기, 갇힘, 탈락, 아이템 나옴·먹음, 보호막, 탱크, 스프링, 덤불, 비행기)은 `GameSound`에,
버튼 소리(클릭 Bt_c_Pop, 준비·준비 취소, 게임 시작, 캐릭터·팀 선택, 나가기, 로그인 성공·실패)는 각 화면에 있습니다.
효과음은 처음 낼 때 PCM으로 풀어 두고 Clip으로 겹쳐 재생합니다.
오디오 장치가 없거나 재생에 실패하면 로그를 남기고 화면은 계속 사용할 수 있습니다.
`src/main/resources/ui`의 두 버튼 PNG는 사용자가 제공한 참고 화면에서 사용 허락을 받아 추출했습니다.

인게임 직접 실행은 `./gradlew run --args="--app.start-screen=game"`을 사용합니다.

### Eclipse와 Codex에서 같은 코드 사용

두 도구에서 같은 저장소 폴더를 사용한다. 외부 수정 후 Eclipse에서 F5로 새로고침하고,
의존성이 바뀌면 프로젝트 우클릭 → Gradle → Refresh Gradle Project를 실행한다.
실행 중인 게임은 종료 후 다시 실행해야 변경 내용을 볼 수 있다.

### 주간 제출용 소스 폴더

제출 기준은 Eclipse에서 실행하는 Hansung_Arcade 저장소다.
Hansung_Arcade_worktrees는 별도 Git 보조 작업 공간이므로 제출하지 않는다.
ZIP에는 src/, gradle/wrapper/, gradlew, gradlew.bat, build.gradle, settings.gradle,
README.md 등 소스와 실행에 필요한 파일을 넣는다.
.git/, .gradle/, build/, bin/, output/과 보조 worktree는 제외한다.
IDE 개인 설정은 필수가 아니며 Eclipse에서는 Gradle 프로젝트로 가져올 수 있다.
제출 시점에는 팀 작업이 통합된 커밋과 실행 상태를 확인한 뒤 그 버전으로 ZIP을 만든다.

로비에는 상태별 탭을 두지 않는다. 대기중 방을 앞에, 게임중 방을 뒤에 정렬한 하나의 목록을 8개씩 표시한다.
로그인은 마스코트 배경과 하단 주황색 입력 패널로 구성하며 1P면 닉네임 1개, 2P면 2개를 받는다. 서버 주소·포트는 입력받지 않고 설정에서 읽으며, 계정 비밀번호는 없다.
